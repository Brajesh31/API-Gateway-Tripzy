## 2. Project status

This repository currently contains package metadata, engineering documentation, diagrams, and GitHub automation. It does not contain a runnable gateway server, public routes, authentication middleware, or verified Tripzy upstream configuration.

## 3. What to include in a support request

- Commit SHA.
- Node.js and npm versions.
- Operating system and environment.
- Exact command and exit status.
- Relevant documentation section or file path.
- Sanitized reproduction steps.
- Expected and actual behavior.
- Correlation ID and safe error code, if a runtime is available.

## 4. What not to share

Never include access tokens, cookies, passwords, signing keys, production environment files, private service URLs, customer data, or complete private payloads.

## 5. Where to report issues

Use GitHub Issues for reproducible bugs, feature requests, documentation improvements, and non-sensitive questions. Use private GitHub Security Advisories for vulnerabilities. Do not disclose exploitable details in public tickets.

## 6. Service-specific questions

Questions about an upstream API require the confirmed service owner and contract. This repository does not currently identify Tripzy service teams or internal endpoints.
